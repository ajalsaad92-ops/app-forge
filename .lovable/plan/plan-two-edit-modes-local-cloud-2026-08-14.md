# Plan — Two edit modes (Local + Cloud), one-click PowerShell, full redesign & onboarding

> مرجع للمطوّرين و**لوفابل** لمعرفة ماذا أُضيف وماذا أُصلح في هذه المرحلة، وكيفية
> حل أي مشكلة قد تظهر. يعمل الفرع على تاريخ `arena/01a000cd-app-forge`.

---

## الملخّص

أضفنا **مسارين لتعديل التطبيقات** — **محلي** و**سحابي** — مع **ربط بزرّ واحد**
بـ PowerShell للتحقق والتثبيت، وإعادة تصميم كاملة للواجهة، وشرح كل الإمكانات
للمستخدم عند أول استخدام، وإظهار جميع الأزرار وحالات العمل في التصميم.

## 0. تقسيم الخطة إلى مراحل (نُفِّذت دفعة واحدة في النهاية)

## 1. ما الذي أُضيف؟

### 1.1 نظام أوضاع التعديل (Local / Cloud)
- ملف `src/lib/bridge-client.ts` أصبح **مدروسًا بالوضع (mode-aware)**:
  - `EditMode = "local" | "cloud"`.
  - `getBridgeBaseFor(mode)` / `getBridgeBase()` / `getLocalUrl()` / `getCloudUrl()`.
  - دوال `bridgeHealth(mode)` و`bridgeHealthInfo(mode)` و`bridgeVerifyTools(mode)`.
  - الوضع يُحفظ في `localStorage` (مفتاح `APPFORGE_MODE`).
  - رابط السحابة قابل للضبط عبر `APPFORGE_CLOUD_URL`، مع قيمة افتراضية من
    `.env` عبر `VITE_APPFORGE_CLOUD_URL`.
- **وضع «محلي»**: الجسر يعمل على جهاز المستخدم (`http://localhost:3000`).
- **وضع «سحابي»**: الاتصال بنفس واجهة `server/apk-bridge.mjs` لكن مستضافة على
  خادم عام (المكان المحدّد) — تُدخل الرابط في إعدادات الاتصال.
- المحرر (`src/routes/editor.tsx`) يعرض **مبدّل أوضاع** في الشريط العلوي، وعند
  تبديل الوضع يتم إفراغ المشروع الحالي وفحص الاتصال بالخادم الجديد تلقائيًا.

### 1.2 الربط بـ PowerShell (زرّ واحد)
- نقطة نهاية جديدة في `server/apk-bridge.mjs`: `GET /api/install.ps1` تولّد سكربت
  PowerShell (`appforge-setup.ps1`) يتحقق من الأدوات (Java/apktool/apksigner/zipalign)
  ويُثبّت الناقص تلقائيًا عبر `winget`.
- في `src/components/SetupGuide.tsx`:
  - زر **«تنزيل سكربت PowerShell»** (يحمّل الـ ps1 جاهزًا للتنفيذ بنقرة).
  - زر **«نسخ أمر التشغيل»** `irm <base>/api/install.ps1 | iex`.
  - زر **«تحقق الآن»** لإعادة الفحص الفوري.
- SetupGuide أصبح **مدروسًا بالوضع**: يستقبل `baseUrl` و`mode`، ويتحقق من الخادم
  الفعّال (محلي أو سحابي) بدل `localhost:3000` الثابت.

### 1.3 مكوّن إعدادات الاتصال
- ملف جديد `src/components/ConnectionSettings.tsx` (نافذة حوار):
  - اختيار الوضع (محلي/سحابي) مع حالة الاتصال لكل وضع.
  - تعديل رابط الجسر المحلي ورابط الجسر السحابي.
  - عرض عدد الأدوات الجاهزة في الوضع المحلي.

### 1.4 مرشد أول استخدام (Onboarding)
- ملف جديد `src/components/Onboarding.tsx` — معالج شاشة كاملة (5 خطوات) يظهر في
  أول استخدام فقط (يتحقق من `APPFORGE_ONBOARDED`):
  1) ترحيب + نظرة على الإمكانات، 2) اختيار وضع التعديل، 3) إعداد الوضع المختار
  (تشغيل الجسر المحلي أو إدخال رابط السحابة) مع زر «تحقق الآن»، 4) شرح كامل
  لكيفية الاستخدام، 5) تأكيد + تنبيه قانوني.

### 1.5 إعادة تصميم كاملة + حالات العمل الظاهرة
- الهوية البصرية تغيّرت كليًا: لون أساسي بنفسجي/أزرق/سماوي (تدرّج `brand-gradient`)
  بدل الأزرق السابق، خلفية أغمق، ألواح زجاجية (`glass-panel`).
- الشريط العلوي في المحرر يعرض: **مبدّل أوضاع**، **زر اتصال**، **زر رفع APK**،
  مؤشر حالة (Bridge/Cloud/Browser)، وأزرار **Setup / AI / Mods / Build / Help**.
- **شريط حالة سير العمل** (Workflow bar) يعرض 6 مراحل بألوان الحالة:
  «ارفع APK → فكّ → عدّل → ابنِ → وقّع → ثبّت» (✓ عند الإتمام / نابض أثناء العمل).
- حالة فارغة (قبل رفع أي ملف) تعرض منطقة رفع APK مع توجيه حسب الوضع المختار.
- الصفحة الرئيسية (`src/routes/index.tsx`) أُعيدت كتابتها: Hero جديد، قسم
  «مساران للتعديل» ببطاقتين قابلتين للاختيار مع حالة الاتصال الحية، خطوات، إمكانات،
  وتنبيه قانوني.

## 2. ماذا أُصلح / حلّ مشاكل؟

| المشكلة السابقة | الحل |
|---|---|
| SetupGuide كان متصلًا بـ `localhost:3000` فقط، فلا يعمل في وضع السحابة | أصبح مدروسًا بالوضع عبر `baseUrl`/`mode` |
| لا يوجد مفهوم «وضع التعديل» — كل شيء يفترض الجسر المحلي | نظام `EditMode` + مبدّل أوضاع + إعدادات اتصال |
| التثبيت يقتصر على أزرار داخل واجهة الجسر | سكربت PowerShell `install.ps1` يفحص ويُثبّت بنقرة |
| لا يوجد شرح أولي للإمكانات | مرشد Onboarding من 5 خطوات |
| حالات الأزرار وسير العمل غير واضحة | شريط حالة سير عمل بست مراحل + مؤشرات حالة لكل وضع |
| لا طريق واضح للاستخدام السحابي | وثّقنا نشر `server/apk-bridge.mjs` على خادم عام وربطه برابط السحابة |

## 3. كيف يُفعَّل الوضع السحابي؟

الواجهة لا تستطيع فكّ/توقيع APK بنفسها. الوضع السحابي يتصل **بنفس** جسر `server/apk-bridge.mjs`
لكنه **مستضاف على خادم Node.js عام** (مثلاً Render / Railway / VPS + PM2):

```bash
# على الخادم
git clone <repo> && cd app-forge
npm i
PORT=3000 HOST=0.0.0.0 APP-FORGE bridge  # أو: npm run bridge
```

ثم يُدخل المستخدم الرابط العام (مثل `https://appforge-bridge.example.com`) في
**إعدادات الاتصال** ← وضع «سحابي». ملاحظة: يحتاج الخادم تثبيت Java + apktool + build-tools.

## 4. حلّ المشاكل الشائعة

- **المؤشر أحمر «Browser»**: الجسر غير متصل. في الوضع المحلي شغّل `npm run bridge`؛
  في الوضع السحابي تأكد من الرابط وفتح المنفذ (CORS مفعّل `*` تلقائيًا في الجسر).
- **زر «رفع APK» معطّل**: لا يوجد خادم متصل. اتبع الإرشاد أعلاه.
- **لا يظهر المرشد عند أول فتح**: تأكد أن `APPFORGE_ONBOARDED` ليس محفوظًا في
  localStorage؛ يمكن حذفه يدويًا لاستعادة المرشد.
- **بعد تغيير الرابط**: اضغط «حفظ» في إعدادات الاتصال، وسيعيد المحرر فحص الاتصال.
- **أوامر winget لا تعمل** (أنظمة غير ويندوز): استخدم زر «تثبيت تلقائي الآن»
  (brew على macOS) أو التثبيت اليدوي الموثّق في SetupGuide.

---

## 5. التحقق

- `npm run build` ينجح (تحقّق أعلاه).
- `npx tsc --noEmit` خالٍ من الأخطاء.
- `npm run bridge` ثم `GET /api/install.ps1` يُرجع السكربت.
- فتح `/` يعرض الصفحة الجديدة، وفتح `/editor` يعرض المرشد أول مرة ثم المحرر الجديد.
